# 需求澄清记录（PRD v0.6 补充）

> 来源：与业务方逐条确认的歧义点结论。与 `PRD.md`、`TEMPLATE-ANALYSIS.md` 共同构成 MVP 开发基线。
>
> 日期：2025-08-22

---

## 1. 部署形态与用户体系

**结论**：单机构内网部署。

**影响**：
- 无多租户；用户体系保持简单：账号 + 角色（检查员 / 管理员，管理员负责知识库与模板管理）。
- 所有 AI 能力（ASR、视觉、LLM、Embedding）的调用端点必须可配置，指向内网可达服务；系统无任何公网依赖（CDN、公网字体、在线激活等均不允许）。
- 交付形态建议：一体化安装包 / docker compose 单机部署。
- 外部 AI 能力不可用时按 PRD §14 降级：不丢原始数据、不伪造结果、保留人工整理能力。

## 2. 视频规格

**结论**：典型检查视频约 1 分钟、60MB 左右、MP4 格式。

**影响**：
- 媒体处理链路可按"单文件、分钟级"设计：普通上传即可，无需分片上传、分布式转码。
- 转写与关键帧提取用短异步任务即可，处理状态机保持简单（待处理 / 处理中 / 成功 / 失败可重试）。
- 存储压力小：单次检查材料量级在百 MB 内，单机磁盘足够。

## 3. 关键画面提取验收标准

**结论**：以"能够支撑照片文书选图"为准。

**影响**：
- 提取策略面向人工选图优化：候选帧覆盖视频全程关键时刻，数量适中（不做海量抽帧）。
- 必须做质量过滤（模糊 / 过暗帧剔除）与相似帧去重，避免选图界面出现大量重复废帧。
- 验收方法：用真实检查视频走通"提取 → 选图 → 生成照片文书"全流程。

## 4. 法规知识库冷启动

**结论**：MVP 预置《中华人民共和国消防法》，其余文档由有权限的用户上传。

**影响**：
- 初始化数据中包含消防法全文，按**条款级切分**（第 X 条）入库，保证检索引用可追溯到具体条款。
- 预置文档需标记为"正式法律法规"类型（与后续用户上传的内部制度等类型区分，见 PRD §6）。

## 5. 模板识别验收基线

**结论**：以 `docs/` 下已提取分析的三份真实模板为准（照片 / 询问笔录 / 监督检查记录表）。

**影响**：
- 模板自动识别的验收集 = 这三份模板；识别规则与字段清单以 `TEMPLATE-ANALYSIS.md` §3 为准，目标覆盖率 100%（含 §4.2 列出的全部难点形态）。
- 填充样式按已确认规则执行：笔录与照片文书填入内容带下划线；记录表检查类型打勾（□→☑）。
- 未知形态模板（下划线空白、内容控件等）按 `TEMPLATE-ANALYSIS.md` §4.3 预留扩展，不纳入本次验收。

## 6. 说话人分离

**结论**：MVP **不要求说话人分离**（2025-08-22 二次确认，原要求放宽）。

**影响**：
- ASR 方案不再强制 diarization，`qwen3-asr-flash` 只需验证基本中文转写效果，阻塞风险解除。
- 转写结果模型简化：分段（时间范围 + 文本），不含说话人标签。
- 询问笔录"问：/ 答："归属改为人工主导：AI 生成初稿时可按语义（疑问句 / 陈述句）预标"问 / 答"作为候选，用户逐段核对修改。PRD §7.3"不得猜测身份"的要求不变——只是没有自动分离结果可用，归属完全由用户确认。
- UI 保留轻量能力：逐段指定 / 修改"问 / 答"角色。
- 转写数据模型预留说话人字段扩展位，便于后续恢复该需求。

## 7. 操作留痕粒度

**结论**：检查事实重要修改与文书确认不仅记录操作人和时间，还**需要可查看的历史记录**。

**影响**：
- 需要独立的修改历史存储：谁、何时、对哪个对象（事实 / 文书字段）、改了什么（旧值 → 新值）。
- UI 提供历史记录查看入口（事实详情、文书页面）。
- 文书状态变化（初稿 ↔ 已确认 / 内容变化后退回初稿）同样进入历史记录。
