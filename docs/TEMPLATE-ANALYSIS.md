# 消防文书 Word 模板结构分析（Spike 报告）

> 分析对象：`docs/照片.docx`、`docs/询问笔录.docx`、`docs/监督检查记录表.docx`
>
> 方法：解压 docx（ZIP），用临时 Python 脚本（标准库 `zipfile` + `xml.etree`）解析 `word/document.xml`，逐段落 / 逐表格单元格提取文本、空白形态与格式特征。未修改任何原始文件。
>
> 日期：2025-08-22

## 1. 三份模板总览

| | 照片.docx | 询问笔录.docx | 监督检查记录表.docx |
|---|---|---|---|
| document.xml 大小 | 6.6 KB | 10.9 KB | 30 KB |
| 主体结构 | 9 个段落，无表格 | 12 个段落，无表格 | 5 个段落 + 1 个 5×5 表格 + 尾部段落 |
| 页面 | **US Letter**（12240×15840 twips）⚠️ | A4 | A4 |
| 页眉/页脚 | 无 | 3 个页脚（首页/奇/偶），内容为"第 X 页 共 4 页" | 无 |
| 媒体文件 | 无 | 无 | 无 |
| 内容控件 `w:sdt` | 无 | 无 | 无 |
| 表单域 `FORMTEXT` | 无 | 无 | 无 |
| 邮件合并域 `MERGEFIELD` | 无 | 无 | 无 |
| `{{占位符}}` / 书签 | 无 | 无 | 无 |
| 下划线字符（`____`） | **无** | **无** | **无** |
| 下划线格式空白 run | 无 | 无（空白 run 均显式 `w:u w:val="none"`） | 无 |
| 创建工具（元数据） | python-docx 生成，Word 保存 | Word 原生 | python-docx 生成，Word 保存 |

**关键结论一：三份模板都没有使用任何"机器友好"的填充机制**（无内容控件、无表单域、无占位符、无书签），也**没有使用最常见的下划线空白**。所有待填位置都是"中文标签 + 普通空格 / 空单元格 / 字面符号"。

**关键结论二：三份模板各自使用不同的空白约定**（详见下表），且单份文档内部也不完全统一（如监督检查记录表中半角 `:` 与全角 `：` 混用）。

## 2. 待填充位置的形态分类

三份模板共出现 **8 种填充形态**：

| 编号 | 形态 | 出现位置 | 示例 |
|---|---|---|---|
| A | 表格"标签单元格 + 相邻空单元格" | 监督检查记录表 | `单位（场所）名称 ‖ (空)` |
| B | 字面复选框字符 `□`（U+25A1，仿宋正文，**非** Wingdings 符号、**非**表单控件） | 监督检查记录表 | `□ 大型群众性活动举办前的检查` |
| C | 标签 + 全角冒号 + 尾随空格（值为"冒号后追加"） | 照片、询问笔录 | `反映内容：␣` |
| D | 一行内多个字段，空格段分隔，字段边界靠"下一个中文标签"识别 | 询问笔录 | `被询问人姓名：␣×6性别：␣×2年龄：…` |
| E | 日期 / 编号骨架（`年 月 日`、`第 号`、`[ ]` 之间夹空格） | 监督检查记录表、询问笔录 | `检查时间:␣×5年␣×2月␣×2日` |
| F | 方括号占位文本 | 照片 | `[此处插入照片]` |
| G | 完全空白的正文区域（无任何脚手架） | 询问笔录 | 表头区之后的问答正文区 |
| H | 标签后**无任何空白**的签名行（值为"标签后追加"） | 监督检查记录表 | `消防监督检查员（签名）：` |

对应的填充操作可归纳为 6 类：

1. **空单元格写入**（A）
2. **字符级替换**：`□ → ☑` 打勾（B）
3. **标签后追加文本 run**（C、H）
4. **空格段替换为文本**（D、E）
5. **占位段落替换为图片**（F，涉及 `word/media` 部件管理）
6. **在指定位置生成全新段落**（G，已超出"填空"范畴，属于内容生成）

### 填充样式要求（业务确认）

- **询问笔录、照片文书**：所有填入 / 生成的内容文本必须带**下划线格式**（run 级 `<w:u w:val="single"/>`），模拟纸质文书"填写内容压在下划线上"的样式；模板原有标签与固定文字保持原样不动。
- **监督检查记录表**：检查类型选中项**打勾**（`□ → ☑`），未选项保持 `□`；其余字段为普通文本填充，不带下划线。
- **询问笔录问答正文区**（形态 G）：生成的问答正文（含"问：/ 答："行）**同样整体带下划线格式**，与表头字段填充样式一致。

## 3. 逐模板字段清单

### 3.1 照片.docx

**结构**：整份文档是**单张照片的证据区块**（照片位 + 6 行标签），多张照片意味着整块纵向重复。除 P0 外无任何显式空白标记，值一律跟在冒号后。

| # | 位置 | 原文形态 | 推断字段 |
|---|---|---|---|
| 1 | P0（居中，仿宋 16pt） | `[此处插入照片]` | **照片图像**（需将占位段落替换为 inline image） |
| 2 | P2 | `反映内容：␣` | 照片反映的现场内容（对应检查事实） |
| 3 | P3 | `拍摄地点：␣` | 拍摄地点 |
| 4 | P4 | `摄制人：␣` | 摄制人 |
| 5 | P5 | `拍摄时间：␣` | 拍摄时间 |
| 6 | P6 | `说明：␣` | 说明 |
| 7 | P7 | `确认人：␣` | 确认人 |
| — | P8 | 含普通 `<w:br/>` 的空段 | 区块分隔 |

注意：
- **填入的值文本需带下划线格式**（`<w:u w:val="single"/>`），即"反映内容 / 拍摄地点 / 摄制人 / 拍摄时间 / 说明 / 确认人"6 个字段的值都压在下划线上；标签本身不加下划线。
- 整页为 US Letter 纸型（其余两份为 A4），疑似建模板时的疏忽；填充时应保持原样，不建议擅自改纸型。
- "反映内容 / 说明"是逐帧字段；"拍摄地点 / 摄制人 / 拍摄时间 / 确认人"在多区块重复时属于同源字段（同一区块组内取值通常一致）。

### 3.2 询问笔录.docx

**结构**：标题 + 表头字段区（P0–P10，纯段落无表格）+ 完全空白的问答正文区 + 页脚页码。所有空白均为**普通空格**（显式 `w:u w:val="none"`，无下划线）。

| # | 位置 | 原文形态（␣=空格） | 推断字段 |
|---|---|---|---|
| 1 | P0（右对齐区） | `第␣×3次` | 询问次数（第几次询问）——无冒号标签，纯行内空白 |
| 2 | P2 | `时间：␣×27至` | 询问起止时间（区间，"至"前为开始，"至"后结束） |
| 3 | P3 | `地点：` | 询问地点（标签后**连空格都没有**） |
| 4 | P4 | `询问人（签名）：␣×14工作单位：` | 询问人签名 ＋ 询问人工作单位（一行两字段） |
| 5 | P5 | `记录人（签名）：␣×6工作单位：␣×15` | 记录人签名 ＋ 记录人工作单位 |
| 6 | P6 | `被询问人姓名：␣×6性别：␣×2年龄：␣×5出生日期：` | 姓名 / 性别 / 年龄 / 出生日期（一行四字段） |
| 7 | P7 | `证件类型：␣×25证件号码：` | 证件类型 / 证件号码 |
| 8 | P8 | `户籍所在地：` | 户籍所在地 |
| 9 | P9 | `现住址：` | 现住址 |
| 10 | P10 | `联系方式：` | 联系方式 |
| 11 | P11（空段）至文末 | （完全空白） | **问答正文区**：模板内没有任何"问：/答："脚手架，正文需整体生成，**生成内容带下划线格式** |
| 12 | 页脚 | `第 {PAGE} 页  共 4 页` | 页码：页码是 `PAGE` 域（动态），但总页数 **"4" 是硬编码字面文本**（非 `NUMPAGES` 域）⚠️ |

注意：
- **所有表头字段填入的值文本需带下划线格式**（含行内多字段、起止时间、第 X 次等）：做法是将空格段替换为带 `<w:u w:val="single"/>` 的值 run，或标签后追加带下划线的 run；下划线同时让行内多字段的边界在视觉上更清晰。
- ⚠️ 页脚"共 4 页"的 4 是写死的。生成内容超过 4 页时总页数会错误。填充/生成后需要修正为 `NUMPAGES` 域或按实际页数重算。
- "（签名）"类字段最终多为手写，AI 填充时可能留空或填姓名，需按业务确认。
- 字段 1、2 的空白位于两个中文字之间且无冒号边界（`第␣次`、`␣至`），属于最难定位的形态 E。

## 4. 规律性与自动识别可行性评估

### 4.1 规律性强的一面

1. **标签词汇高度业务化且有限**：`名称/地址/时间/地点/签名/证件/联系方式…`，配合全角冒号 `：` 是极强的识别信号。
2. **表格采用经典"标签-值"邻接布局**：空单元格左侧（或上方）必有中文标签，方向性稳定。
3. **无嵌套表格、无浮动文本框、无图片水印**，结构树浅而干净。
4. 待填区域**格式与标签格式一致**（同字体字号），追加文本时无需复杂格式推导。

### 4.2 不规律的、需要算法兜底的一面

| 难点 | 实例 | 影响 |
|---|---|---|
| 空白形态不统一 | 三份模板分别用"冒号后追加 / 空格段 / 空单元格 / 字面□ / 方括号占位" | 识别器必须是**多信号组合**，不能靠单一规则 |
| 标点不统一 | 记录表用半角 `:`（`编号:`、`检查时间:`），其余全用全角 `：` | 标签正则需兼容半/全角 |
| 行内多字段 | 询问笔录 P4–P7 一行 2–4 个字段，靠空格段分隔 | 需按"标签：␣+标签："模式切分；`性别：␣×2年龄：` 仅 2 空格，阈值切分不可靠，**必须做标签词典匹配** |
| 无标签行内空白 | `第␣×3次`、`␣×27至` | 只能靠"夹在中文字之间的空格段 + 语义（第次/至）"识别 |
| 标签后零空白 | `地点：`、`消防监督检查员（签名）：` | "冒号后无空格"不等于"不是字段"；需把"标签行本身就是字段"作为一条规则 |
| 伪固定文字 | 抬头单位名 | 自动识别会把 `桐乡市消防救援大队` 当固定文本跳过，换单位复用时漏识别 |
| 标签竖排拆分 | `单[BR]位[BR]情[BR]况` | 单元格文本提取要先把 BR 拼接成连续字符串 |
| 硬编码总页数 | 页脚"共 4 页"的 4 是字面量 | 生成后需修正，否则超页出错 |
| 完全无脚手架的正文区 | 询问笔录问答区 | 不属于"识别填写位置"，属于"内容生成"，两者要分开处理 |

### 4.3 可行性结论

> **对这三份模板：规则引擎（非 AI）即可达到接近 100% 的自动识别，且填充操作全部可用 python-docx 级别的库完成。**

建议的识别规则（按优先级）：

1. **表格标签-值对**：空单元格 + 左/上邻接中文标签 → 字段（覆盖记录表 8/11 的字段）；
2. **字面复选框组**：`□ + 选项文字` → 枚举字段（记录表 R0）；
3. **标签行**：匹配 `^[^：:]{1,12}[：:]\s*$` 或 `标签：␣*$` → 追加型字段（照片 6 个、笔录 6 个、签名行）；
4. **行内多字段切分**：`标签：␣+标签：…` 按标签词典切分（笔录 P4–P7）；
5. **骨架空白**：`[␣]`、`第␣号/次`、`␣年␣月␣日`、`␣至` → 组合字段（编号、日期、起止时间、次数）；
6. **方括号占位**：`[…]` 整段 → 占位替换（照片位）。

置信度设计：规则 1–3 高置信可直接采用；规则 4–6 中低置信，**应展示给用户确认后再固化映射**。对这三份模板之外的未知模板（如下发文书常见的下划线空白 `____`、内容控件），需补充对应规则——本次三份模板未覆盖这些形态，属于已知的覆盖缺口。

### 4.4 对填充实现的启示

- 6 类填充操作（§2）中，1–4 是纯文本 run 操作；5（插图片）需管理 media 部件与关系 ID；6（生成问答正文）是"在锚点段落后插入新段落"，需继承正文格式（仿宋、字号、行距）。
- **下划线填充实现**：模板空白本身是普通空格、无下划线格式，因此下划线必须由填充方添加——值 run 设置 `<w:u w:val="single"/>`，字体字号继承所在段落格式，标签 run 不动。对短值字段，可选在值两侧补"带下划线的空格"以维持下划线的视觉长度（是否补足、补足到多长，作为字段映射的配置项）。
- **原地填充**（在空格段位置写值）vs **追加填充**（值跟在标签后）会改变版面宽度：行内多字段行（笔录 P6）填入长值会挤压后续字段导致换行错乱。对这类行建议"替换空格段、保留标签相对顺序"，并接受自然换行；或对值长度设限。
- 复选框 `□` 是 FangSong 字体的普通字符，替换为 `☑`（U+2611）无字体兼容问题；若业务要求其他打勾样式（如 `√` 覆盖、加粗 `■`），只是字符级配置差异。
- 生成问答正文时：每个生成段落的文本 run 统一带 `<w:u w:val="single"/>`（含"问：/ 答："行），段落格式继承表头区正文样式（仿宋、行距）；同时页脚总页数（硬编码 "4"）必须同步处理。
